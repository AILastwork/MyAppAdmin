# MyAppAdmin

Текущая версия: `0.16.7`.

Windows desktop приложение на Python + PySide6 для администраторских операций вместо старого веб-интерфейса MyAppAdm.

Целевая ОС: Windows в доменной среде. Целевой Python: 3.12. Код совместим с Python 3.11+, но для PySide6 и будущей сборки `.exe` основной вариант - Python 3.12.

## Что уже есть

- Каркас PySide6-приложения с тёмной темой, Matrix-темой и боковым меню.
- При запуске показывается анимированная заставка с дата-центром, серверами, сетевыми папками, GLPI/Yandex/МФУ, сканирующим лучом, сетевыми искрами, glow-слоями и бегущими сигналами загрузки; переход к главному окну сделан плавным кроссфейдом.
- Страницы: Главная, Создать пользователя, Поиск AD, Почта Yandex, `1C / V8i`, Шаблоны баз, Принтеры, GLPI, История и Описание программы. Настройки показываются только текущему Windows-пользователю из Domain Admins.
- Локальные настройки в `%APPDATA%\MyAppAdmin\config.json`.
- Локальный SQLite audit DB по умолчанию в `%APPDATA%\MyAppAdmin\audit.db`.
- Сервисный слой для `ibases.v8i`, `1CEStart.cfg`, пользовательских папок и подготовки ACL-команд `icacls`.
- Реальный поиск пользователей, групп и OU AD через Python/LDAPS (`ldap3`) с настройками `ad_ldap_server`, `ad_read_user`, `ad_read_password`.
- В создании пользователя есть ФИО одной строкой с авторазбором на поля, автоматическое формирование свободного login по AD, генерация AD/Yandex-паролей, загрузка OU/групп из AD и единая кнопка `Создать пользователя`.
- Почта Yandex 360 и файлы 1C создаются в этом же сценарии только по отмеченным галочкам; во время выполнения показывается прогресс.
- Единый сценарий повторяет веб-версию: AD-пользователь создается через LDAPS от имени подтвержденного администратора, затем выполняются почта, папки, файлы 1C и ACL. Пароль Yandex по умолчанию совпадает с паролем AD.
- Папка пользователя, папка `scan`, корень файлов 1C и шаблон `ibases.v8i` задаются в форме создания пользователя и сохраняются для следующего создания. Корень 1C по умолчанию: `\\osnova.local\fs\IBASE`.
- OU и группы выбираются непосредственно из AD или вводятся вручную, без предварительных списков разрешений.
- В `1C / V8i` базы можно искать, отмечать чекбоксами без отдельной текстовой галочки, добавлять из выбранного шаблона и сохранять только отмеченные строки.
- Удаление строк в `1C / V8i` и `Шаблоны баз` выполняется по квадратным галочкам; синее выделение таблицы не влияет на удаление.
- В `Поиск AD` кнопка `Вид` настраивает видимые колонки, выбор группы/OU показывает ее участников, а выбранного пользователя можно заблокировать, разблокировать или сменить ему пароль после повторной проверки доменного администратора.
- В `Шаблоны баз` доступен редактор шаблонов: создание, переименование и удаление файлов, добавление/удаление баз, сохранение и предпросмотр итогового `.v8i`.
- При создании пользовательских файлов перезапись существующего `ibases.v8i` доступна только через отдельный чекбокс.
- В `Описание программы` встроена актуальная справка по назначению, первому запуску, всем разделам, безопасности и правилу версионирования.
- Безопасный AD-create: административные группы блокируются неизменяемым правилом по имени, маркерам `admin/администратор`, SID/RID, `adminCount` и цепочке вложенного членства. Редактируемого списка исключений больше нет.
- Чтение Yandex token-файла в INI-формате или legacy-формате `API_yandex360.txt` без вывода token в UI.
- Раздел `Почта Yandex` после проверки доменного администратора AD читает пользователей выбранной организации в фоновом потоке с индикатором загрузки, позволяет расширить таблицу пользователей, показывает статус и доступные даты в человекочитаемом виде, создает пользователей с автоматическим login и блокирует/разблокирует учетные записи через Yandex 360 API.
- Загруженную выборку пользователей Yandex 360 можно сохранить в оформленный Excel-файл `.xlsx` с закреплённой шапкой, фильтрами и полным набором доступных полей.
- Для реальных операций AD, Yandex и создания пользовательских папок добавлен диалог проверки доменной учетной записи: введенная учетная запись проходит LDAPS bind и проверку членства в стандартной администраторской группе AD.
- Секреты настроек (`ad_read_password`, `kyocera_admin_password`, `kyocera_smb_password`) сохраняются в `config.json` через Windows DPAPI, а не открытым текстом.
- В форме создания пользователя формируется типовое письмо сотруднику с почтовым и AD-доступом, паролями и ФИО; после успешного создания оно автоматически копируется в буфер обмена. В разделе `Почта Yandex` формируется отдельное письмо только по почте.
- Отдельная кнопка повторного создания папок/ACL удалена: файловая структура и права выполняются автоматически только в общем сценарии создания пользователя.
- Параметры, сохраняемые из рабочих разделов, и внутренние служебные значения скрыты из формы настроек.
- Выбор общего `printers.json` через проводник, добавление принтера по IP в локальный `%APPDATA%\MyAppAdmin\printers.local.json`, предпросмотр Kyocera-записи и запуск реального добавления через `kyocera_add.py`; пример JSON есть во встроенном разделе `Описание программы`.
- В разделе `Принтеры` выбранный принтер можно удалить: локальные записи удаляются из `printers.local.json`, общие - из выбранного общего `printers.json` после отдельного подтверждения.
- В принтерах указаны проверенные модели Kyocera ECOSYS M3145dn/M3540idn; при вводе ФИО автоматически формируются login и email в домене `mkd-osnova.ru`.
- Для Kyocera ECOSYS MA4500x добавлено автоматическое определение HTTPS Command Center RX. Добавление контакта выполняется в фоне: интерфейс остается доступным, журнал обновляется в реальном времени, а полоса показывает текущий этап.
- Перед запуском Kyocera выполняется быстрая проверка TCP 80/443. Общий лимит операции составляет 180 секунд; операцию можно отменить кнопкой, а закрытие приложения требует подтверждения и останавливает дочерний процесс. Уже принятый принтером POST отмена не откатывает.
- При добавлении локального принтера можно сохранить IP, имя/hostname и модель, например `10.14.32.47`, `KM1E33BC`, `ECOSYS MA4500x`.
- Скрипт получил безопасный режим `--check-only`, нормализацию IP без схемы и адаптивный POST на основе реального `form action` и скрытых полей прошивки. Диагностика входа и формы успешно прошла на M3540idn, MA4500x, M3145dn, M2040dn и M2135dn.
- После успешного POST Kyocera больше не запускается шумная текстовая проверка адресной книги: принтер уже принял запись, а список на части моделей обновляется через JS/кэш с задержкой.
- Нижний журнал Kyocera в разделе `Принтеры` показывает человеческие этапы операции и скрывает технические пробы прошивки вроде `add_model_candidate`, 404-кандидатов и debug-файлов.
- После успешной работы скрипта Kyocera проверяется папка `USERFOLDER\login\scan`. Если она отсутствует, приложение предлагает создать ее после подтверждения учетной записи Domain Admins и назначить фиксированные ACL.
- Раздел `GLPI` подключен без REST API: по введенным GLPI-логину и паролю выполняется вход в веб-интерфейс, загружается список компьютеров и дальше локально ищется рабочее место по login, ФИО, имени ПК, IP, MAC или серийному номеру.
- В `GLPI` добавлен расширенный режим таблицы, поиск по частям имени/фамилии с транслитерацией и человекочитаемая карточка ПК; IP показывается только как IPv4 без `fe80::`.
- Раздел `История` получил отдельную иконку скрученного свитка и показывает последние события локального audit-журнала.
- Консольные служебные команды Windows (`whoami`, `icacls`) и Kyocera worker запускаются скрыто, чтобы при старте и рабочих операциях не мигали черные окна.
- В корне проекта находится автономная инструкция `MyAppAdmin_First_Run.html` для подготовки нового хоста и первого запуска EXE.
- Общая папка приложения по умолчанию: `\\osnova.local\fs\IT\MyAppAdmin`; там ожидаются шаблоны 1C, `API_yandex360.txt` и `printers.json`.
- Тесты сервисного слоя в `tests/`.

## Установка для локального запуска

```powershell
cd <путь к AD_ADMIN_EXE>
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e .[dev]
```

Если Python launcher `py` не установлен, используйте полный путь к Python 3.12.

## Запуск

```powershell
cd <путь к AD_ADMIN_EXE>
.\.venv\Scripts\Activate.ps1
python -m app.main
```

При первом запуске приложение создаст конфиг:

```text
%APPDATA%\MyAppAdmin\config.json
```

## Сборка EXE

```powershell
.\.venv\Scripts\python.exe -m pip install -e .[build]
.\.venv\Scripts\python.exe -m PyInstaller --clean --noconfirm MyAppAdmin.spec
```

Готовый переносимый файл: `dist\MyAppAdmin.exe`. Python на целевом 64-битном Windows-хосте не требуется. В EXE не включаются локальный `config.json`, Yandex token-файлы, `printers.json` и сохраненные пароли; приложение использует настройки текущего пользователя из `%APPDATA%\MyAppAdmin`.

Раздел "Настройки" доступен только текущему Windows-пользователю из Domain Admins. В нем можно менять:

- домен и `base_dn`;
- LDAPS-настройки AD: `ad_ldap_server`, `ad_ldaps_port`, `ad_read_user`, `ad_read_password`, `ad_search_limit`;
- тему интерфейса: `app_theme` (`dark` или `matrix`);
- каталог шаблонов 1C;
- путь к Yandex token-файлу;
- путь к `printers.json`;
- базовый URL GLPI: `glpi_base_url`;
- параметры `kyocera_*` для адресной книги МФУ.

Пути пользовательской папки, scan и 1C, профиль `ibases.v8i` и видимые колонки AD/Yandex сохраняются непосредственно из рабочих разделов и не дублируются в настройках. Внутренние `audit_db`, `service_mode_enabled` и scan-учетка также скрыты из формы.

## Проверки

```powershell
python -m pytest
```

Последняя проверка: `102 passed` на Python 3.12, включая offscreen-проверки PySide6-интерфейса, GLPI HTML-парсер и открытие экспортированного `.xlsx` в Microsoft Excel.

## Важные ограничения текущего этапа

- Реальное создание AD-пользователя выполняется кнопкой `Создать пользователя` через LDAPS от имени администратора, введенного в диалоге подтверждения. `ad_read_user`/`ad_read_password` используются для чтения и поиска AD.
- Создаваемый пользователь не может быть добавлен в административные группы. Проверка выполняется до создания по имени и повторно после разрешения DN по атрибутам AD и цепочке родительских групп.
- Создание и блокировка пользователей Yandex 360 выполняются через API с OAuth token из защищенного token-файла. Перед рабочими операциями в разделах `Почта Yandex` и `Создать пользователя` появляется диалог проверки доменной учетной записи.
- Пароль, введенный в диалог проверки, не сохраняется в настройках, preview или audit. Для создания пользователя он используется в памяти только на одну операцию: LDAPS bind, проверка группы и AD-create выполняются в одном соединении. Файловые операции по SMB/NTFS выполняются правами Windows-процесса, под которым запущено приложение.
- Пароли, сохраненные в настройках, лежат в `config.json` как `dpapi:v1:...` и расшифровываются только Windows DPAPI для текущего пользователя/машины.
- Если в старом `config.json` пароль уже был открытым текстом, на Windows он будет прочитан и автоматически перезаписан в DPAPI-формате при следующей загрузке конфига.
- Поле `Статус изменен` показывает дату последней блокировки или разблокировки аккаунта. Если статус никогда не менялся, отображается `не изменялся`.
- Kyocera добавление подключено через `kyocera_add.py`; перед боевым использованием проверьте настройки Kyocera/SMB на тестовом МФУ.
- Самоподписанный сертификат Command Center RX принимается автоматически. Если стандартный TLS завершается SSL-ошибкой, скрипт повторяет соединение в отдельном совместимом режиме для старой прошивки.
- Kyocera сначала проверяется по TCP 80/443; вся операция ограничена 180 секундами. При отмене или подтвержденном закрытии приложения дерево worker-процесса завершается.
- Проверка Domain Admins разрешает создание отсутствующей папки `scan`, но сама операция с UNC выполняется правами текущего Windows-процесса.
- Доступ к папкам через `icacls` фиксирован: Domain Admins и создаваемый пользователь получают Full, а `scan_user.osnova.local` получает Modify только на папку `scan`.
- Если назначение ACL для пути завершилось ошибкой, отключение наследования для этого пути пропускается.
- GLPI работает через веб-интерфейс, потому что REST API недоступен. Пароль вводится только на время загрузки списка и не сохраняется; при изменении HTML GLPI парсер может потребовать адаптации.

## Состав публичной версии

- `app/` - desktop-приложение PySide6 и сервисный слой.
- `tests/` - автоматические проверки.
- `kyocera_add.py` - подключенный Kyocera worker/CLI.
- `packaging/windows_version_info.txt` и `MyAppAdmin.spec` - сборка Windows EXE.
- `MyAppAdmin_First_Run.html` - автономная инструкция первого запуска.

В публичный git-коммит не включаются локальные конфиги, token-файлы, `printers.json`, audit DB, собранный `dist/`, `.venv/`, диагностические HTML/Payload Kyocera, внутренняя история разработки и legacy-копия старого веб-проекта.
